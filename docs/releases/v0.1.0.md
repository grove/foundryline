**Release notes: prepared for review; no Git tag or GitHub Release has been published.**

**Qualification:** **ACCEPTED FOR A NARROW, TESTED MANUAL WORKFLOW** by the maintainer on 2026-10-18, recorded in [issue #6](https://github.com/grove/foundryline/issues/6). The source and receipt [review](../discover-v0.1-qualification-review.md) describes the exact scope and its limits.

## Welcome to the first Foundryline blueprint!

Foundryline is a collection of copyable recipes for building and looking after software with AI. You bring your own coding assistant and repository. There is no Foundryline service to install.

**v0.1 focuses on Discover:** a repeatable way to look for a few worthwhile improvements in a repository, check the evidence, and prepare **reviewable issue drafts** rather than trusting every suggestion an AI makes.

## What you can use

- **[Manual Discover runbook](../../patterns/discover.md):** how to choose a repository and specific revision, ask Gapline to investigate read-only, check original requirements and existing issues, and draft an unpublished issue with Intentline guidance.
- **[Beginner-friendly README](../../README.md):** an introduction, a three-step getting-started example, and links to the tools.
- **[Authored examples](../../examples/manual-discover/README.md):** learning cases for supported findings, no findings, and missing access. These are **synthetic examples**, not actual agent runs.
- **[Real RepoTend pilot](../../examples/repotend-pilot/README.md):** pinned public source, two independently started agent threads on the same operator host, a source-unavailable refusal, a source-supported finding, and an **unpublished** issue proposal. Retained commands, source manifest, reports, events and usage allow review.
- **[Reference checks](../../checks/test_manual_discover.py) and [pilot reader/receipt checks](../../checks/test_pilot_reader.py):** deterministic tests of documentation, sample integrity and retained event/source records, exercised in GitHub Actions. These tests do not launch an agent or validate target-project behavior.

**No new full-stack orchestration code or product runtime is needed for v0.1.**

## What the first pilot actually showed

The test used **macOS and Codex CLI 0.163.0** with a pinned, operator-prepared, public RepoTend source bundle and an explicitly invoked `gapline-audit` skill.

Both main runs returned the same **source-supported** concern: RepoTend's Markdown remediation preview generated a suggested apply command without the chosen repository's `--root` argument. That could cause the command to target the caller's working directory under some conditions. **No wrong-repository write was reproduced.**

The negative run deliberately withheld source files. The agent reported **UNAVAILABLE / NOT ASSESSED** instead of inventing findings. The report and draft issue preserve counterevidence, original promises, exceptions and scope limits.

## Important limits

**This is acceptance of a narrow manual reference, not a claim of a fully autonomous or generally secure factory.**

- The reproduced runs shared the coordinating operator, physical host, provider/runtime and source preparation; this is not independently administered cross-host reproduction.
- Read-only controls and source-reader call logs are documented, but additional host/provider interfaces were not exhaustively challenged. This is **not universal sandbox certification**.
- Some transitive RepoTend sources were outside the selected bundle. The pilot did **not** assess the full implementation, execute RepoTend tests, or prove a runtime bug.
- Exact model identity and billable cost were unavailable. Retained token counts are not a whole-task cost estimate.
- Discover **does not** automatically publish GitHub issues, change code, run schedules, merge PRs or deploy. The **Deliver** and **Maintain** Foundryline recipes remain planned rather than qualified.
- A saved `intentline-plan` contract is optional and separately authorized; `intentline-issue` guidance for a draft does not publish an issue.

## Getting started

1. Read the [simple README](../../README.md) and the [manual Discover recipe](../../patterns/discover.md).
2. Install the Gapline agent skill in a supported coding-agent host, explicitly invoke it on a selected repository/revision with **host-enforced read-only access**, and ask for at most three source-grounded findings.
3. Review the findings, verify original behavior and duplicates, and use Intentline issue guidance to prepare a **NOT PUBLISHED** draft. Decide independently if you want to create a real issue.

Your host and permission boundaries may differ from the tested Codex environment; verify those capabilities before relying on them.

## What's next?

The next useful experiments are a **Maintain** recipe composing RepoTend's deterministic repository-health audit into reviewable issue proposals, and then a qualified *manual trigger* / optional *scheduled, read-only* workflow. Actual publishing or repair always requires its own authorization.
