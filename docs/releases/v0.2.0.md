## What is Foundryline?

Foundryline is a set of **copyable recipes** for using existing development agents and tools responsibly. There is **no Foundryline server, proprietary coding engine or mandatory workflow orchestrator**. You bring your own repository, coding agent and approved permissions.

For v0.2.0, the practical focus is **three manual workflows**:

| Recipe | When to use it | What actually qualified |
| --- | --- | --- |
| [**Discover**](../../patterns/discover.md) | Find a potentially valuable problem and prepare an **unpublished** issue proposal with evidence. | The previously **accepted scoped v0.1** macOS/Codex pilot, a separately started same-operator reproduction and a withheld-source refusal; original [qualification decision](../discover-v0.1-qualification-review.md). |
| [**Maintain**](../../patterns/maintain.md) | Inspect repository health and triage RepoTend advisory findings. | Real macOS pinned local audit and independent-workspace/same-host agent adoption, missing-target exit 2, and a **distinct real manual `workflow_dispatch`** on GitHub-hosted Ubuntu, with read-only config, real results and failure control. [Accepted limits](../maintain-v0.2-qualification-review.md). |
| [**Deliver**](../../patterns/deliver.md) | Take an approved task through an existing coding agent, frozen candidate and bounded check evidence to a *human-approved* PR decision. | Actual user-authorized RepoTend CLI change; real original single-S1 Intentline export; separately selected R1/R2 behavior checks on pinned Proofline/macOS, unlinked gap, invalid mapping refusal, and protected native canaries. [Accepted limits](../deliver-v0.2-qualification-review.md). |

## What v0.2.0 does **not** promise

**No scheduled intake.** A previous conditional roadmap once associated v0.2 with manual *and scheduled* audits. This release deliberately **defers scheduling**: the only GitHub audit trigger deliberately tested as a human action was `workflow_dispatch`. No standing issue-writing privilege, autonomous coding, fixes, merge/deploy authority or periodic agent invocation is enabled.

**No universal verification.** A PASS means a specific selected check passed on a recorded candidate and host, not that the complete original request or every potential security property is satisfied. **`coverage_completeness: UNKNOWN`** remains. An Intentline DRAFT (even structurally valid) does not grant human approval. A reviewer shared an operator/provider on these tests; no universal isolated-host certification or independent adversarial assessment is claimed.

**No blanket cross-platform support.** The Discover live pilot used a particular macOS/Codex version; the manual Maintain local run used macOS Node 26.12.0 and the button-triggered run Ubuntu Node 22.20.0; the external native Deliver check used GitHub macOS 15.7.9 ARM64, Python 3.12.10, Node 22.16.0 and native Codex CLI **0.162.1** with a **specific** host permissions revision. Native Proofline checks are not generally qualified for Linux/Windows, and no silently unprotected fallback is permitted.

**Historical failures stay failed.** Earlier Node-based native checks on the unpatched sandbox did **not** run product assertions; the corrected run never changes their old statuses. A negative command map refusal is not a product failure.
